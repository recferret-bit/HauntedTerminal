# Tech

- Web app: Vite 6, TypeScript 5 (strict), Three.js 0.180, xterm.js 5 with the fit addon.
- Entry: `pages/index.html` is the issue hub (the Vite root is `pages/`). The game is `pages/play.html`, served at `/play`, `/play/<chapter>`, and `/play/<chapter>/<level>` (a `floor/<n>` segment jumps a classic floor). `/hub.html` redirects to `/`.
- Commands: `npm start` / `npm stop` / `npm restart` / `npm run status` (the dev server as a background process, see below), `npm run build` (typecheck + bundle), `npm run preview`, `npm run quality` (see `architecture.md`). `npm run dev` is the same server in the foreground.
- Running the stack: `npm start` launches Vite on port 5173 in the background, waits until it answers, prints the URLs and returns; it is a no-op when already running. `npm stop` stops it and only ever touches processes started from this project (other Vite servers on the machine are left alone). Log: `scripts/harness/out/stack/stack.log`. Other port: `npm start -- --port 5174` (or `STACK_PORT=5174 npm start`; agents use the env form, since some agent shells refuse commands containing `--port`). Agents must use these, never `npm run dev`, which blocks the shell.
- Chapter editor: `pages/chapter-editor.html`, served at `/editor`, `/editor/<chapter>` and `/editor/<chapter>/<level>` (`?tab=` picks the tab). Built on shared `src/editor-core/`, it edits `chapters/` through the dev-only API `/api/chapters` (`scripts/harness/lib/chapter-api.mjs` + `editor-api-common.mjs`) and previews the game with `/play/...?draft=1`. Smoke test: `node scripts/harness/editor-smoke.mjs`.
- Comix editor: `pages/comix-editor.html`, served at `/comix-editor`, `/comix-editor/<slug>` and `/comix-editor/<slug>/<target>` (`?tab=` picks the tab). Built on `src/editor-core/`, it edits connected `comix/<slug>/` sequences through `/api/comix` (`scripts/harness/lib/comix-api.mjs` + `editor-api-common.mjs`), supports bidirectional 2D/3D viewport <-> Inspector selection, and previews `/cinematic.html?draft=1&editor=1`. Tests: `node scripts/harness/editor-unit-test.mjs` and `node scripts/harness/comix-editor-smoke.mjs`.
- Terminal Lab: `pages/terminal-lab.html`, served at `/terminal-lab` and `/terminal-lab/<lab-id>` (`?tab=` picks the Inspector tab). A test bench for the terminal: place enemies, pickups, files, riddles, tasks and NPCs, play them in the real game (an iframe on a throwaway pack, `?draft=1&lab=1`), and script them. Nobody takes damage. A lab is one `*.lab.json` document (`src/terminal-lab/lab-types.ts`); it is saved in the browser and, through the dev-only `/api/terminal-lab` (`scripts/harness/lib/terminal-lab-api.mjs`), in `scripts/harness/terminal-lab/`. It never writes `chapters/` or `comix/`. Tests: `node scripts/harness/terminal-lab-unit.mjs`, `node scripts/harness/terminal-lab-api-test.mjs`, `node scripts/harness/terminal-lab-smoke.mjs`; headless runs: `node scripts/harness/terminal-lab.mjs --all`.
- Laptop Lab: `pages/laptop-lab.html`, served at `/laptop-lab` (`?state=<laptop state>`, `?speed=0|0.4|1`, `?mute=1`). The developer's inventory laptop: it opens, dives in, boots and runs a desktop whose apps (JS Pad, Web Weaver) run real JS in a Worker and real pages in a `sandbox="allow-scripts"` iframe, with loop protection; seven coding tasks with deterministic checks. Real keys press its keys, the real pointer moves its trackpad finger. Progress stays in `localStorage` (`haunted.laptop.progress`). Lab only: the chapter does not give the laptop yet. Tests: `node scripts/harness/laptop-unit.mjs`, `node scripts/harness/laptop-lab-smoke.mjs`.
- Storybook: `pages/storybook.html`, served at `http://localhost:5173/storybook.html` (models, textures, FX under the real renderer). URL options: `src/storybook/domain/options.ts`.
- Property-based tests: `scripts/harness/property-tests.mjs` with `fast-check` (devDependency, pinned), suites in `scripts/harness/props/<feature>.mjs`, run in `npm run quality`.
- Deploy: Netlify, through the project power `haunted-ship` (`.kiro/powers/haunted-ship/`; install with `kiro-cli powers install <abs path>`, which copies it, so reinstall after editing). `node .kiro/powers/haunted-ship/skills/ship/scripts/ship.mjs preview` runs `npm run quality`, the chapter verify and the build, uploads `dist/` as a draft with `netlify-cli@27.20.0` and plays the chapter on the preview URL; `prod` deploys that same build after the user's yes. The bundled MCP server is `@netlify/mcp@1.22.1`, for questions only. Credentials: `netlify login` or `NETLIFY_AUTH_TOKEN`, never in the repo. Site id: git-ignored `scripts/harness/out/ship/site.json`.
- MCP for the agent team (`.kiro/specs/mcp-devtools-and-forge/`): declared per agent in `scripts/harness/agents-build.mjs`, never in `.kiro/settings/mcp.json` (stays empty). `haunted-forge` (`scripts/mcp/haunted-forge/`, `@modelcontextprotocol/sdk@1.32.2`, `zod@4.6.7`): `list_assets`, `list_levels`, `get_level`, `validate_level`, `solve_level`, `write_level` (only after validation, a 0-death solve and an etag match; canonical writer and catalog recompile, like `/editor`). Chrome DevTools MCP (`chrome-devtools-mcp@1.13.0`, devDependency, run with `node` and Node's compile cache because Kiro does not wait for slow MCP servers) for `qa` only. Tests: `npm run quality:mcp`; real CLI: `node scripts/harness/mcp-probe.mjs`.
- Agent team: `.kiro/agents/` (Kiro CLI 3.3 V3 profiles; every profile with `permissions` also carries `"allowedTools": []`, or the CLI drops it). Launch with `kiro-cli --agent lead-dev`; Kiro Crew app: `docs/AGENTS_CREW.md`.
- Content tooling is plain Node `.mjs` scripts: `scripts/harness/` (comic drawing, chapter & comix compilers, editor unit/smoke suites, screenshots, playthrough) and `.kiro/skills/*/scripts/` (validators and self-tests).

## Current state

Ported and refactored to the architecture rules: `src/procgen`, `src/shaders`, `src/storybook`, `src/contracts`, the playable shell (`src/game`, `src/renderer`, `src/ui`, `src/cinematic`, `src/chapters`, `src/sandbox`), the shared workstation editors (`src/editor-core`, `src/chapter-editor`, `src/comix-editor`), the Terminal Lab (`src/terminal-lab`, labs in `scripts/harness/terminal-lab/`), and the Laptop Lab (`src/laptop`). Chapter packs live in `chapters/` and compile to `src/chapters/generated/` (`node scripts/harness/generate-chapter.mjs`); animated 3D comix packs live in `comix/` and compile to `src/cinematic/generated/` (`node scripts/harness/generate-comix.mjs`). Do not claim a skill command passed unless you ran it.

## Rules

- Prefer deterministic, zero-LLM validators for anything that decides pass/fail.
- Pin dependency versions when adding packages.
- Chapters and Comixes are declarative (`declarative-chapters.md`, `declarative-comix.md`): `npm run quality:declarative` rejects chapter ids, level ids, comix sequence/page ids, and `spec.index === N` in `src/`.
- Keep generated files (`src/chapters/generated/`, `src/cinematic/generated/`, rendered PNGs) reproducible from the specs; regenerate, do not hand-edit.
