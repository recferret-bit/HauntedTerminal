# Tech

- Web app: Vite 6, TypeScript 5 (strict), Three.js 0.180, xterm.js 5 with the fit addon.
- Entry: `pages/index.html` is the landing's Home (the Vite root is `pages/`); its header tabs open `/desktop.html`, `/achievements.html` and `/comix.html`, each its own page with one shared header rendered by `src/hub/nav.ts` (the Comix page lists one tile per chapter with progress, plus locked roadmap tiles). Unit check: `node scripts/harness/hub-unit.mjs`; smoke: `node scripts/desktop/landing-smoke.mjs`. The game is `pages/play.html`, served at `/play`, `/play/<chapter>`, and `/play/<chapter>/<level>` (a `floor/<n>` segment jumps a classic floor). `/hub.html` redirects to `/`.
- Commands: `npm start` / `npm stop` / `npm restart` / `npm run status` (the dev server as a background process, see below), `npm run build` (typecheck + bundle), `npm run preview`, `npm run quality` (see `architecture.md`). `npm run dev` is the same server in the foreground.
- Running the stack: `npm start` launches Vite on port 5400 in the background, waits until it answers, prints the URLs and returns; it is a no-op when already running. `npm stop` stops it and only ever touches processes started from this project (other Vite servers on the machine are left alone). Log: `scripts/harness/out/stack/stack.log`. Other port: `npm start -- --port 5174` (or `STACK_PORT=5174 npm start`; agents use the env form, since some agent shells refuse commands containing `--port`). Agents must use these, never `npm run dev`, which blocks the shell.
- Chapter editor: `pages/chapter-editor.html`, served at `/editor`, `/editor/<chapter>` and `/editor/<chapter>/<level>` (`?tab=` picks the tab). Built on shared `src/editor-core/`, it edits `chapters/` through the dev-only API `/api/chapters` (`scripts/harness/lib/chapter-api.mjs` + `editor-api-common.mjs`) and previews the game with `/play/...?draft=1`. Smoke test: `node scripts/harness/editor-smoke.mjs`.
- Comix editor: `pages/comix-editor.html`, served at `/comix-editor`, `/comix-editor/<slug>` and `/comix-editor/<slug>/<target>` (`?tab=` picks the tab). Built on `src/editor-core/`, it edits connected `comix/<slug>/` sequences through `/api/comix` (`scripts/harness/lib/comix-api.mjs` + `editor-api-common.mjs`), supports bidirectional 2D/3D viewport <-> Inspector selection, and previews `/cinematic.html?draft=1&editor=1`. Tests: `node scripts/harness/editor-unit-test.mjs` and `node scripts/harness/comix-editor-smoke.mjs`.
- Terminal Lab: `pages/terminal-lab.html`, served at `/terminal-lab` and `/terminal-lab/<lab-id>` (`?tab=` picks the Inspector tab). A test bench for the terminal: place enemies, pickups, files, riddles, tasks and NPCs, play them in the real game (an iframe on a throwaway pack, `?draft=1&lab=1`), and script them. Nobody takes damage. A lab is one `*.lab.json` document (`src/terminal-lab/lab-types.ts`); it is saved in the browser and, through the dev-only `/api/terminal-lab` (`scripts/harness/lib/terminal-lab-api.mjs`), in `scripts/harness/terminal-lab/`. It never writes `chapters/` or `comix/`. Tests: `node scripts/harness/terminal-lab-unit.mjs`, `node scripts/harness/terminal-lab-api-test.mjs`, `node scripts/harness/terminal-lab-smoke.mjs`; headless runs: `node scripts/harness/terminal-lab.mjs --all`.
- Interactive Terminal Field Manual: `pages/manual.html` (served at `/manual` and `/manual.html`, `?cmd=`, `?q=`, `?page=`; linked from `/` landing, `/chapters.html`, and `/dev.html`) and in-game modal `#manual-book-modal` on `/play` (`manual [query]`, `F1`, `#tty-manual-btn`; keeps battle turn timer running). Styled as a Comic-book hardcover spread (`src/ui/manual-book*.ts`, `src/game/manual-*.ts`, `src/styles/manual-book.css`) and carried in-game as inventory item `manual` (`item.manual`, `vibecoder.dev_manual`). Spec: `.kiro/specs/inventory/items/manual/`. Tests: `node scripts/harness/manual-unit.mjs`, `node scripts/harness/manual-smoke.mjs`.
- Chapter Motherboard Map: interactive PCB schematic dialog `#chapter-map-dialog` on `/play` (`#hud-map`, `.item-slot.item-map`, `F3`, or `map [level]`; keeps battle turn timer running), built declaratively from `ChapterPack` (`src/ui/chapter-map-model.ts`, `src/ui/chapter-map.ts`, `src/styles/chapter-map.css`) with a live chip inspector and two-step in-place deploy, and carried as inventory item `map` (`item.map`, `vibecoder.dev_map`). Spec: `.kiro/specs/inventory/items/map/`. Tests: `node scripts/harness/manual-unit.mjs`, `node scripts/harness/manual-smoke.mjs`.
- Laptop Lab: `pages/laptop-lab.html`, served at `/laptop-lab` (`?state=<state>`, `?speed=0|0.4|0.5|1`, `?mute=1`) with Quest Check & `RunReport` Inspector + `window.__laptop`. In chapter 1, `item.laptop` unlocks `edit`/`sed` and `F4` opens it over `/play` (`src/play/laptop.ts`). Tests: `laptop-unit.mjs`, `laptop-lab.mjs --verify`, `laptop-lab-smoke.mjs`, `play-laptop-smoke.mjs`.
- Audio Lab & Audio Inspect: `pages/audio-lab.html` (`/audio-lab`, `src/audio-lab/`, `window.__audioLab`), `src/audio/config.ts` (`SFX_TRIM`, `LOOP_GAINS`), `audio-gen.mjs inspect <cue>...|--all [--json]`, `audio-lab-unit.mjs`, `audio-lab-smoke.mjs`.
- Storybook FX Workbench: `pages/storybook.html` (`/storybook.html?tab=fx`) displays `validateFxPreset` metrics (`fxInfo`), Play/Pause, 12fps frame scrubber, per-layer toggles, and custom word preview (`window.__storybook`).
- Visual audit (qa): `scripts/harness/visual-audit.mjs` with `pngjs` and `pixelmatch` (devDependencies, pinned). It captures the player-facing screens in headless Chrome over CDP (seeded `Math.random`, storm off; play screens on a stepped virtual clock that also steps the stage through `window.__stage`, other pages frozen after a real-time settle), records real-time screencast filmstrips and throttled frame timing, runs detectors, and diffs against `docs/qa/baselines/` (masks in `masks.json`). Output: `scripts/harness/out/visual/`. `--selftest` runs it on fixture pages in `scripts/harness/visual/fixtures/`.
- Property-based tests: `scripts/harness/property-tests.mjs` with `fast-check` (devDependency, pinned), suites in `scripts/harness/props/<feature>.mjs`, run in `npm run quality`.
- Deploy: Netlify, through the project power `credits-ship` (`.kiro/powers/credits-ship/`; install with `kiro-cli powers install <abs path>`, which copies it, so reinstall after editing). `node .kiro/powers/credits-ship/skills/ship/scripts/ship.mjs preview` runs `npm run quality`, the chapter verify and the build, uploads `dist/` as a draft with `netlify-cli@27.20.0` and plays the chapter on the preview URL; `prod` deploys that same build after the user's yes. The bundled MCP server is `@netlify/mcp@1.22.1`, for questions only. Credentials: `netlify login` or `NETLIFY_AUTH_TOKEN`, never in the repo. Site id: git-ignored `scripts/harness/out/ship/site.json`.
- Release and local desktop (specs `.kiro/specs/release-tags-power/`): power `credits-tauri-local` (`.kiro/powers/credits-tauri-local/`) builds the Tauri app for this machine from the working tree, unversioned and unpublished, into git-ignored `scripts/harness/out/tauri-local/` and opens it (`tauri-local.mjs`, `--no-open`, `--dry-run`, `--selftest`). Power `credits-release` (`.kiro/powers/credits-release/`) prints a plan, and with `--yes` checks a clean `main` equal to `origin/main`, a free tag and `package.json` version, runs the gates, pushes tag `v<version>` (desktop-release.yml builds the installers and the Release) and makes the Netlify preview; Netlify production stays the user's second yes through `credits-ship`. Both are the user's command only: every team agent's shell denies them.
- MCP for the agent team (`.kiro/specs/mcp-devtools-and-forge/`): declared per agent in `scripts/harness/agents-build.mjs`, never in `.kiro/settings/mcp.json`. `credits-forge` (`scripts/mcp/credits-forge/`, 18 tools across assets/chapters/comix/labs, per-tool writer fences in `agent-mcp.mjs`) + Chrome DevTools MCP (`chrome-devtools-mcp@1.13.0`, `qa` only). Tests: `npm run quality:mcp`; CLI: `node scripts/harness/mcp-probe.mjs`.
- Agent team: `.kiro/agents/` (Kiro CLI 3.3 V3 profiles; every profile with `permissions` also carries `"allowedTools": []`, or the CLI drops it). Launch with `kiro-cli --agent lead-dev`; Kiro Crew app: `docs/AGENTS_CREW.md`.
- Sound generation (spec `.kiro/specs/audio-agent/`): the ElevenLabs CLI (`elevenlabs` 1.13.0, Keychain OAuth login) is reached only through `scripts/harness/audio-gen.mjs` (owner `lead-dev`): `plan <cue>` is a dry run; `--generate` (sound-designer only) refuses over 15,000 credits a run or under a 30,000 reserve, and runs `ffmpeg` when installed. Shells refuse `elevenlabs` and `--output`.
- Desktop & Steamworks (`scripts/desktop/`, `.github/workflows/desktop-release.yml`, specs `.kiro/specs/steam-launch-funnel/` and `.kiro/specs/steamworks-store-release/`): `npm run desktop:generate` (`generate-tauri-steam.mjs`) writes the git-ignored `src-tauri/` Tauri v2 + optional `steamworks` (`0.11.0`) Rust shell synced 1:1 with the 15 `ACH_*` local achievements (`src/chapters/achievements.ts`); `npm run desktop:verify` checks zero external CDN URLs and bundled `public/fonts/*.woff2`; `npm run desktop:test` runs `desktop-unit.mjs`; pushing a `v*` git tag builds macOS, Windows, Linux, and portable offline bundles on GitHub Releases. Playbook: `docs/STEAM_RELEASE_PLAYBOOK.md`.
- Flying bats (specs `.kiro/specs/flying-bats/`, `.kiro/specs/flying-bats-rework/`): every 20-60 s a flock of 1-6 `prop.bat_flying` models (side / 3/4 cartoon bats with two-part 12 fps scalloped wings and glowing `powerAmber` 3/4 eyes lined in `ink`; `prop.bat` is a perched upside-down wall roost bat) crosses the play stage corner to opposite corner on a cubic Bézier with sine easing (`src/renderer/bat-path.ts` pure, `stage-bats.ts` stepper), mirroring and pitching along the travel tangent so bats travel head-first, and triggering the `bat_wings` fast wing-clap SFX on flock entry (plus a staggered second burst on flocks of 4+ bats). Decoration only; frozen while `stormPaused`, off under reduced motion. Tests: `architecture-unit.mjs`, `audio-unit.mjs`.
- Full screen (spec `.kiro/specs/fullscreen-mode/`): `src/chapters/fullscreen.ts` is the one helper. F11 toggles it on every player page, and the Esc menu has a Fullscreen toggle; the web build never saves the choice. The Tauri main window starts full screen on every launch (`fullscreen: true` in `tauri-templates.mjs`) and toggles through the window plugin (`core:window:allow-set-fullscreen` / `allow-is-fullscreen`). Tests: `hub-unit.mjs`, `desktop-unit.mjs`.
- Terminal skins (spec `.kiro/specs/terminal-skins/`): six window skins for the play page's terminal (iterm2, terminal-app, putty, windows-terminal, gnome-terminal, vt100), listed once in `src/contracts/terminal-skins.ts`. Only the window chrome changes (`src/styles/terminal-skins.css`, keyed on `#terminal-bezel[data-skin]`); the terminal body never does. Switched with `skin <id>` or the Esc menu picker, saved under `out-of-credits:terminal-skin:v1` (not in previews or labs); with nothing saved the OS picks (macOS iterm2, Windows windows-terminal, Linux gnome-terminal).
- Content tooling is plain Node `.mjs` scripts: `scripts/harness/` (comic drawing, chapter & comix compilers, editor unit/smoke suites, screenshots, playthrough), `scripts/desktop/`, and `.kiro/skills/*/scripts/` (validators and self-tests).

Do not claim a skill command passed unless you ran it.

## Rules

- Prefer deterministic, zero-LLM validators for anything that decides pass/fail.
- Pin dependency versions when adding packages (enforced across `dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies` and `package-lock.json` `packages[""]` by `scripts/quality/check-deps.mjs`).
- Static analysis (`scripts/quality/eslint.config.mjs`) covers `src/**/*.ts` and `scripts/{quality,hooks,desktop,mcp,harness}/**/*.mjs` and is wired into `.kiro/hooks/static-analysis-on-save.json` and `.kiro/hooks/quality-chain-on-stop.json`.
- Chapters and Comixes are declarative (`declarative-chapters.md`, `declarative-comix.md`): `npm run quality:declarative` rejects chapter ids, level ids, comix sequence/page ids, and `spec.index === N` in `src/`.
- Keep generated files (`src/chapters/generated/`, `src/cinematic/generated/`, rendered PNGs) reproducible from the specs; regenerate, do not hand-edit.
