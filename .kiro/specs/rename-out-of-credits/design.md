## Pieces

- **One name module** `src/contracts/brand.ts`: `PROJECT_NAME`, `PROJECT_NAME_CAPS`, `PROJECT_SLUG`, `LEGACY_SLUG`. The inner layer, so `chapters`, `hub`, `ui`, `play` and the laptop import it. Node scripts that cannot import TypeScript keep the slug as a literal checked by the grep gate.
- **Migration** `src/contracts/legacy-keys.ts` (pure, takes a `Storage`): `migrateLegacyKeys(storage)` copies each `haunted-terminal:*` and `haunted.laptop.*` key to its new name when the new key is absent, keeps the old key (a rollback stays possible), and is idempotent. Called once at the start of `play/` bootstrap, each hub entry (`src/hub/boot.ts`), and the labs. The new key wins when both exist.
- **Save format**: exports write `format: "out-of-credits-save"`. The importer (browser and `steam-bridge-rs-template.mjs`) accepts both format strings and both file-name families. Auto-Cloud: the desktop bridge reads `haunted-terminal-save.json` from `app_data_dir` if the new file is absent, then writes the new name.
- **Strings**: pages (`pages/*.html` titles, descriptions), README, `package.json` and lock, `src/` text, desktop generator (product name, bundle id, installer and portable names), workflow, docs.
- **Team and tooling**: `scripts/harness/agents-build.mjs` table, regenerated `.kiro/agents/` (the user owns that folder, so it is regenerated by the script, never hand-edited), `git mv` of the four `.kiro/powers/haunted-*` folders, `.kiro/skills/haunted-art-direction`, `scripts/mcp/haunted-forge`, and `.mcp` server names inside the table. Every reference follows in the same commit. Installed copies of the powers need `kiro-cli powers install` again (user step, listed in the report).
- **Past records**: names only, with a script that replaces the table above and refuses to touch lines it did not match (diff reviewed).
- **Story**: the title and tagline sit in chapter and comix specs. `chapters-designer` and `comix-designer` change them through the intake and sequence skills, then the generators recompile `generated/`.

## Gate for leftovers

A new quality check `scripts/quality/check-legacy-name.mjs`, wired into `npm run quality`: fails on `Haunted Terminal`, `HauntedTerminal`, `haunted-terminal`, `hauntedterminal` in tracked files, except an allow-list (`legacy-keys.ts`, its unit test, the save importer and its fixtures, `check-legacy-name.mjs`). Allowed because Req 11 permits them.

## Order and risks

1. Branch, then the brand module, migration and its unit test (with the old key kept in the allow-list).
2. Mechanical rename by script with the table, reviewed by diff; then manual fixes (casing, URLs, caps).
3. Team, powers, skills and MCP rename; regenerate agents; `quality:agents`.
4. Desktop and save format.
5. Story text after the user approves a tagline.
6. Gates and a full playthrough.

Risks: a missed reference breaks a hook or agent (the agents gate and the new leftover gate catch it); the `.kiro/agents/` regeneration depends on the build script's output being accepted; the `fingerprint` hash may change if a model or texture embeds the name (diff and explain it).
