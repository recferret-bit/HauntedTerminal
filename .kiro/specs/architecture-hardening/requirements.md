# Architecture hardening: requirements

Status: done (requirements, design and tasks approved by the user 2026-11-26, delegated: "go with your recommendations"; retroactive: written 2026-11-26 from commit 1905207, which landed without a spec)

Capability: a refactor of the whole codebase toward KISS, DRY and clean architecture, enforced by new deterministic gates. It adds exact dependency pinning, ESLint, a runtime-cycle check and a dead-code check to `npm run quality`; one generic state machine (`src/contracts/state-machine.ts`) behind the battle, play lifecycle and UI modals; one play-page event bus (`src/play/events.ts`); table-driven shell dispatch for both shells; shared unix applets and `kiro` subcommands; a split of the metagame data out of `src/chapters/catalog.ts`; the removal of four modules; two new Kiro hooks; two new Node unit suites; an `npm run test` script; and four more strict TypeScript flags. Source: `git show --stat 1905207` (277 files, +8615/-4404) and `docs/reviews/2026-11-26-code-review-boost.md`. No new `src/<area>/` and no new `pages/*.html` were created (`git show --diff-filter=A --name-only 1905207`).

Every item was written from commit 1905207 and is confirmed by the Decisions below. Paths are those of that commit unless a later change is named. Where the code has moved since, the item says so.

### Gates and tooling

1. WHEN `npm run quality` runs, THE SYSTEM SHALL run, in this order after `tsc --noEmit`: `quality:deps`, `quality:lint`, `quality:root`, `quality:size`, `quality:layers`, `quality:cycles`, `quality:deadcode`, `quality:declarative`, `quality:specs`, `quality:dup`, `quality:agents`, `quality:legacy-name`, `quality:brands`, `quality:mcp`, `quality:props` (`package.json` `scripts.quality`), and fail on the first gate that fails.
2. WHEN `quality:deps` runs (`scripts/quality/check-deps.mjs`), THE SYSTEM SHALL fail IF any entry of `dependencies`, `devDependencies`, `optionalDependencies` or `peerDependencies` is not an exact semver version, or IF `package-lock.json` `packages[""]` differs from `package.json` in name, version, keys or versions, or is missing.
3. THE SYSTEM SHALL pin every dependency exactly: `@xterm/addon-fit` 0.10.0, `@xterm/xterm` 5.5.0, `three` 0.180.0, `@types/three` 0.180.0 (were `^` ranges), upgrade `typescript` from `^5.8.2` to 5.9.3 and `vite` from `^6.2.0` to 6.4.6, and add the dev dependencies `eslint` 10.15.0, `@eslint/js` 10.0.1 and `typescript-eslint` 8.74.0 (84 new `node_modules/` entries in `package-lock.json`).
4. WHEN `quality:lint` runs (the `lint` script delegates to it: `"lint": "npm run quality:lint"`), THE SYSTEM SHALL run ESLint with `scripts/quality/eslint.config.mjs` over `src`, `scripts/{quality,hooks,desktop,mcp,harness}`, `social/media` and `.kiro/powers` (the last two were added after the commit), ignoring `src/chapters/generated/**`, `src/cinematic/generated/**`, `dist/**`, `dist-desktop/**`, `src-tauri/**`, `scripts/harness/out/**` and `skills/**`; with `@eslint/js` recommended, `typescript-eslint` recommended, shared hygiene rules (`no-var`, `prefer-const`, `eqeqeq` (null ignored), `no-debugger`, `no-unneeded-ternary`, `no-useless-return`, `no-duplicate-imports`, `no-self-compare`, `no-unreachable-loop`, `no-constant-binary-expression`, `default-case-last`, `no-useless-rename`, `object-shorthand`), and for `src/**/*.ts` also `no-explicit-any`, `no-unused-vars` (`_` prefix allowed), `consistent-type-imports` (inline), `no-eval`, `no-implied-eval`, a ban on `innerHTML`, `outerHTML` and `insertAdjacentHTML`, and `max-depth` 6. For `.mjs` scripts `@typescript-eslint/no-unused-vars` is off and the core `no-unused-vars` applies (`_` prefix allowed).
5. WHEN `quality:cycles` runs (`scripts/quality/check-cycles.mjs`), THE SYSTEM SHALL fail IF any runtime import cycle (a strongly connected component of size > 1, or a self-import) exists among `src/**/*.ts`, ignoring type-only imports and re-exports. It has no allowlist.
6. WHEN `quality:deadcode` runs (`scripts/quality/check-deadcode.mjs`), THE SYSTEM SHALL fail IF a `src/**/*.ts` module is unreachable from `pages/*.html` script tags or from `.mjs` scripts under `scripts/` and `.kiro/skills/` (static, dynamic and Worker imports), IF an exported runtime value or exported type is never imported elsewhere, or IF a `.css` file under `src/` or `pages/` is not referenced transitively; `src/chapters/generated/` and `src/cinematic/generated/` are excluded, and `src/contracts/brand.ts` and `src/procgen/index.ts` are treated as public API files. Adding a file to that allowlist needs a user decision recorded in a Kiro spec; a comment above the list in `check-deadcode.mjs` says so.
7. THE SYSTEM SHALL set `noImplicitReturns`, `noImplicitOverride`, `useUnknownInCatchVariables` and `forceConsistentCasingInFileNames` in `tsconfig.json`, in addition to the existing `strict`, `noUnusedLocals`, `noUnusedParameters` and `noFallthroughCasesInSwitch`.
8. WHEN a file matching `src/**/*.ts` or `scripts/(quality|hooks|desktop|mcp|harness)/**/*.mjs` is saved, THE SYSTEM SHALL run, report-only, `quality:lint`, `check-cycles.mjs`, `check-layers.mjs` and `check-size.mjs src scripts/desktop` (hook `.kiro/hooks/static-analysis-on-save.json`, PostFileSave, timeout 60 s).
9. WHEN an agent turn stops, THE SYSTEM SHALL run the static chain `tsc --noEmit`, `check-deps`, `quality:lint`, `check-size`, `check-layers`, `check-cycles`, `check-deadcode`, `check-declarative`, `quality:dup`, `check-legacy-name`, `check-brands` (hook `.kiro/hooks/quality-chain-on-stop.json`, Stop, timeout 90 s).
10. WHEN `npm run test` runs, THE SYSTEM SHALL run `classic-unit.mjs`, `architecture-unit.mjs`, `battle-unit.mjs`, `audio-unit.mjs`, `editor-unit-test.mjs`, `terminal-lab-unit.mjs`, `laptop-unit.mjs`, `manual-unit.mjs`, `hub-unit.mjs`, `legacy-keys-unit.mjs`, `scripts/desktop/desktop-unit.mjs`, `social-unit.mjs` (added after the commit), `generate-chapter.mjs --verify` and `generate-comix.mjs --verify`, in that order. It is a manual convenience, not part of `npm run quality`; a change under `src/` is not called done until it passes.
11. WHEN `node scripts/harness/classic-unit.mjs` runs, THE SYSTEM SHALL check the classic session in Node through Vite SSR (17 tests: the five-floor speedrun with 0 deaths, the floor mechanics, `&&`/`||` exit codes, the turn and pause clock, SSD backups, the tutorial, the `rm` refusal (req 20), POSIX command conformance, Tab completion, and that every classic actor model is in `ModelCatalog`). It replaces the browser-only `src/game/selfcheck.ts`.

### Patterns in `src/`

13. THE SYSTEM SHALL provide one generic, pure state machine in `src/contracts/state-machine.ts` (`TransitionTable`, `nextMachineState`, `reachableStates`, `createStateMachine` with `can`, `send`, `reset`, `subscribe`), and SHALL drive these from a declarative `TransitionTable`: the battle (`BATTLE_TRANSITIONS`, `src/game/battle.ts`, through `nextMachineState`), the Kiro companion and the agent director (`src/game/{kiro,agents}.ts`), the play lifecycle (`src/play/lifecycle.ts`), the Terminal Lab run control (`src/terminal-lab/run-control.ts`), and the UI machines in `src/ui/{chapter-map,code-editor,dialog-box,dialog-orchestrator,esc-menu,manual-book,manual-book-search,modal-dialog,visual-lab-panel}.ts`. Using `createStateMachine` + `TransitionTable` is a convention, not a gate; a machine that steps its table with `nextMachineState` (`battle.ts`) is compliant (`architecture.md` says so).
14. THE SYSTEM SHALL model the play page phase as `PLAY_PHASE_TRANSITIONS` over `boot | intro | play | outro | stats` with events `ENTER_INTRO`, `BEGIN_PLAY`, `BEGIN_ENDING`, `FINISH_OUTRO`, `PLAY_AGAIN`, `SWAP_LAB` (`SWAP_LAB` reaches `play` from every phase; `play` goes back to `intro` by `ENTER_INTRO` or `PLAY_AGAIN`, `stats` goes to `intro` by `PLAY_AGAIN` or `ENTER_INTRO`, `boot` goes to `play` by `BEGIN_PLAY`), plus a set of `PauseReason`s, and SHALL derive clock pause, storm pause, shell block and HUD visibility from that state (`createPlayLifecycle`, `derive`).
15. THE SYSTEM SHALL route play-page events through one `PlayEventBus` (`createPlayBus`, `src/play/events.ts`, which stays in `play/` because its events are play-only; kinds `apply-events`, `apply-tick`, `paint`, `sync-pause`, `ending-begin`, `play-again`, `run-start`, `skin-change`, `modal`, `floor-restart`, `session-swapped`), and SHALL open, close and toggle the four modals (`manual`, `map`, `hint`, `menu`) only through `{ kind: 'modal' }` events handled by `routeModalAction`.
16. THE SYSTEM SHALL dispatch shell commands through lookup tables instead of `switch` statements: `CLASSIC_HANDLERS` in `src/game/session-shell.ts` (classic shell) and the exported `CHAPTER_HANDLERS` in `src/chapters/session-shell.ts` (chapter shell). An unknown command exits 127 with `<cmd>: command not found` in the classic shell (plus a `sudo` joke) and `bash: <cmd>: command not found (try 'help' or 'hank')` in the chapter shell.
17. THE SYSTEM SHALL implement the unix applets shared by both shells once (the chapter shell is the reference for output, exit codes and stderr, since it is the shipped game; the classic shell agrees with it), in `src/game/unix-applets.ts` (among them `wc`, `grep -c`, `head`, `tail`, `cut`, `sed`, `rev`, `chmod` through `applyChmodMode`), and the `kiro` subcommands once, in `runKiroCommand` (`src/game/kiro-commands.ts`), called by both `cmdKiro` (`src/game/puzzle.ts`, `src/chapters/session-kiro.ts`).
18. THE SYSTEM SHALL keep the static metagame data (`RIG_PERKS`, `GRIMOIRE_ENTRIES`, `BESTIARY_DOSSIER` and their types) in `src/chapters/metagame-data.ts`, re-exported by `src/chapters/catalog.ts` (591 to 343 lines).
19. THE SYSTEM SHALL use one VFS ancestry helper, `isDescendantOrSelf` in `src/game/tree.ts`, in place of the three earlier parent walks (`isCwdInside`, `isWithin` and an inline loop).
20. IF the player runs `rm` on the VFS root, on a node without a parent, or on the current directory or one of its ancestors, in either shell, THEN THE SYSTEM SHALL refuse with `rm: refusing to remove '<path>'`, exit 1, and remove nothing (`cmdRm`, `src/chapters/session-fs.ts` and `src/game/commands-fs.ts`, both through `isDescendantOrSelf`). The classic shell gave `...: you are standing in it` for an ancestor, after its permission, busy and veto checks; it was aligned to the chapter shell on 2026-11-26 (decision 14), and `classic-unit.mjs` asserts it.
21. THE SYSTEM SHALL remove `src/game/selfcheck.ts` (replaced by req 11), `src/sandbox/mock-director.ts` (the sandbox's `MockDirector`), `src/renderer/html-escape.ts` (`escHtml`) and `src/pages/html-text.ts` (`esc`), and SHALL build DOM with the text-node builders of `src/contracts/dom.ts` (`dom`, `el`, `setText`, `replayClass`; `ui/dom-lite.ts` re-exports them and `renderer/stage-overlay.ts` imports `el`) and `h()` in `src/editor-core/dom.ts`. `contracts/dom.ts` is the one documented exception to "contracts are pure" (decision 8).
22. THE SYSTEM SHALL keep the gates green after the refactor: `npm run quality:props` passes (87 properties on 2026-11-26 after the `rm` alignment; the review listed 86), `npm run quality:fingerprint` is byte-identical to the tree before the commit (decision 19), and the `npm run test` suites pass (`docs/reviews/2026-11-26-code-review-boost.md` section 3 lists them and 8 headless Chrome smoke suites; the smoke suites were not re-run for this spec).

23. THE SYSTEM SHALL assign `scripts/harness/{classic-unit,architecture-unit}.mjs` to `lead-dev` (the `lead-dev` writes in `scripts/harness/agents-build.mjs`, its row in `.kiro/agents/prompts/team-rules.md`, and `OWNED` in `scripts/quality/check-agents.mjs`), so that each has exactly one owner. `scripts/quality/{check-deps,check-cycles,check-deadcode,eslint.config}.mjs` and the two hooks `static-analysis-on-save` and `quality-chain-on-stop` are the user's infrastructure: no agent edits the gates that judge it. Every other owner in the table is confirmed.
24. THE SYSTEM SHALL keep the properties of `lead-dev`-owned code (`PlayLifecycle`, `AppBus`, `PlayEventBus`, `BATTLE_TRANSITIONS`, the UI transition tables) in the existing suites `props/gameplay-fsm.mjs` and `props/terminal-ui.mjs`; the owner of the suite changes them when `lead-dev` reports a behaviour change (`docs/PROPERTY_TESTS.md` says so).
25. WHEN `quality-chain-on-stop` runs, THE SYSTEM SHALL report each failing step and exit 0 (report-only, 90 s timeout); the blocking gate is `npm run quality`.
